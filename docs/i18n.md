# Translating violation messages

The framework-free core emits **hardcoded English**. Every violation also carries a stable
`messageKey`, and that is the hook for translation.

## Why not translate in the core

`src/Core` and `src/DTO` must work with no framework loaded — that is the package's central promise
and a test enforces it. CI4's `lang()` is not available there, and inventing a translation layer of
our own would mean a second, worse one for every consumer that already has a real one.

So the core does the honest minimum: an English sentence for the developer reading a stack trace, and
a machine-readable key for the application to translate.

## The shape of a violation

```php
$violation = $taxid->validate('12345678A', 'ES')->firstViolation();

$violation->code;         // ViolationCode::CheckDigitFailed  — branch on this
$violation->messageKey;   // 'taxid.violation.check_digit_failed'  — translate this
$violation->message;      // 'The tax ID check digit is invalid.'  — log this
```

The key is always `taxid.violation.` plus the enum's backing value, so it is derivable and stable.

## Translating in a CodeIgniter 4 app

Create `app/Language/es/Taxid.php`:

```php
<?php

return [
    'violation' => [
        'blank'               => 'Introduce un identificador fiscal.',
        'too_short'           => 'El identificador fiscal es demasiado corto.',
        'too_long'            => 'El identificador fiscal es demasiado largo.',
        'illegal_characters'  => 'El identificador fiscal contiene caracteres no válidos.',
        'unknown_country'     => 'No damos soporte todavía a ese país.',
        'country_required'    => 'Indica el país del identificador fiscal.',
        'bad_length'          => 'La longitud no es válida para ese país.',
        'malformed_structure' => 'El formato no es válido para ese país.',
        'check_digit_failed'  => 'El dígito de control no es correcto. Revisa el número.',
        'scheme_mismatch'     => 'Ese número es válido, pero no del tipo que pedimos aquí.',
        'reserved_value'      => 'Ese número nunca se ha emitido: parece un valor de prueba.',
        'nothing_to_validate' => 'No hay nada que validar.',
    ],
];
```

Then resolve the key. CI4 lowercases the first segment of a language key, so
`taxid.violation.check_digit_failed` finds `app/Language/<locale>/Taxid.php`:

```php
$violation = taxid_validate($input, 'ES')->firstViolation();

if ($violation !== null) {
    $message = lang($violation->messageKey);
}
```

## Or branch on the code

Often better, because the wording that helps a user depends on your form, not on the violation:

```php
use Daycry\TaxId\Enums\ViolationCode;

$message = match ($violation?->code) {
    ViolationCode::Blank            => lang('Checkout.taxIdRequired'),
    ViolationCode::CheckDigitFailed => lang('Checkout.taxIdTypo'),
    ViolationCode::ReservedValue    => lang('Checkout.taxIdPlaceholder'),
    ViolationCode::CountryRequired  => lang('Checkout.chooseCountry'),
    default                         => lang('Checkout.taxIdInvalid'),
};
```

`CheckDigitFailed` and `ReservedValue` genuinely want different words: the first is almost always a
typo worth asking the user to re-check, the second is almost always test data that reached
production.

## What is not translated

**Scheme names** (`'CPF — Cadastro de Pessoas Físicas'`, `'Y-tunnus — business identity code'`) are
registry data, written in the language the scheme is actually known by, with an English gloss. They
are not translation keys, and translating "CPF" would not help anyone.

**Country names** are English. If your application already has a localized country list — most do —
use that and key it on `ParsedTaxId::$countryCode`.
